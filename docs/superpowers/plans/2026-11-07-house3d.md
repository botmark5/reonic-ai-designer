# House3D Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `<House3D design={DesignResponse} home={Home} mode="planner"|"homeowner" />` — a stylised German family house in React Three Fiber whose PV panels, battery, inverter, wallbox and heat pump follow the design, with energy-flow lines, orbit camera, tooltips and a static-image fallback.

**Architecture:** Pure, node-testable TypeScript decides *what* to show (panel layout on the roof plane, which components are visible, their labels and flow paths). A pure three.js builder makes the house geometry (testable for triangle budget). Thin R3F components render those specs and own animation/camera. A client wrapper lazy-loads the canvas (`next/dynamic`, `ssr:false`) and falls back to a PNG.

**Tech Stack:** three 0.187, @react-three/fiber 9, @react-three/drei 10 (CameraControls, Html, Line, PerformanceMonitor), Next 16 / React 19.3. Tests: `node:test` run via `npx -y tsx@4 --test` (no new package.json entries, so no clash with session B).

**Spec:** `docs/prompts/session-c-3d.md` (+ `docs/api.md`, `docs/design/README.md`, `docs/design/tokens.json`)

## Review Focus

1. **Very large PV (e.g. 25 kWp = 56 panels)** → more than the main roof holds: overflow goes to the garage roof, the rest is reported as `overflow` and shown in the PV tooltip ("4 panels don't fit on this roof"), never drawn floating off the roof. → Task 2 test `overflow_spills_to_garage_then_reports`.
2. **`include: false` or null sizes** (`pv.kwp: null`, `battery.kwh: null`) → component hidden, no flow line to it, no NaN in labels. → Task 3 test `excluded_and_null_components_hidden`.
3. **Design changes while mounted** (refine adds a wallbox) → only the changed component animates; panels already shown don't re-drop. → Task 5 (keys = stable slot ids `pv-main-r0c3`), verified in browser.
4. **No WebGL / slow device / SSR** → PNG fallback renders, no crash on server render. → Task 8 test `chooseRenderMode`.
5. **Unusual roof (pitch 0°/60°, azimuth 90° east)** → layout still within margins, house rotates so the panel plane faces the azimuth. → Task 2 test `layout_respects_margins_for_any_pitch`.

### Task 2: Panel layout

**Files:** Create `layout.ts`, `__tests__/layout.test.ts`

**Interfaces — Produces:**
```ts
export const PANEL = { w: 1.134, h: 1.762, gap: 0.02, kwp: 0.45 } // portrait, metres
export type RoofPlane = { id: "main" | "garage"; width: number; slope: number; // along-eave, eave→ridge, metres
  margin: { side: number; eave: number; ridge: number } }
export type PanelSlot = { id: string; plane: RoofPlane["id"]; u: number; v: number } // centre, u along eave from plane centre, v from eave up
export type Layout = { slots: PanelSlot[]; requested: number; placed: number; overflow: number }
export function panelCount(kwp: number | null | undefined, maxPanels?: number): number
export function capacity(plane: RoofPlane): { cols: number; rows: number; total: number }
export function layoutPanels(n: number, planes: RoofPlane[]): Layout
```
Algorithm: fill planes in order; per plane `rows = ceil(k/cols)`, full rows first, the last (partial) row centred; the block sits against the eave margin (as installers mount from the gutter up) and each row is centred in u. Slot ids `${plane}-r${row}c${col}` so a slot keeps its id when n grows.

- [ ] **Step 1:** Tests:
  - `panelCount`: `9.0 → 20`, `10.8 → 24`, `null → 0`, `0 → 0`, `(14.4, 25) → 25`.
  - `capacity` for `{width: 13, slope: 6.1, margin: {side: .4, eave: .4, ridge: .3}}` → `cols 10, rows 3, total 30`.
  - `layout_places_n_centred`: 20 panels on that plane → 20 slots, 2 full rows of 10, mean u ≈ 0 (±1e-9), no two slots closer than `PANEL.w` in u when same v.
  - `overflow_spills_to_garage_then_reports`: 40 panels on [main(30), garage(cap 8)] → 30 main, 8 garage, `overflow 2`.
  - `layout_respects_margins_for_any_pitch`: for slopes 3.0, 6.1, 9.0 every slot satisfies `|u| + PANEL.w/2 ≤ width/2 - side` and `v - PANEL.h/2 ≥ eave`, `v + PANEL.h/2 ≤ slope - ridge`.
  - `ids_stable_when_growing`: ids of layout(20) ⊂ ids of layout(24) when both have full first rows.
- [ ] **Step 2:** Run → FAIL. **Step 3:** Implement. **Step 4:** Run → PASS. **Step 5:** Commit `feat(house3d): panel layout`.

### Task 4: House geometry

**Files:** Create `houseGeometry.ts`, `__tests__/houseGeometry.test.ts`

**Interfaces — Produces:**
```ts
export type HouseDims = { length: 12; depth: 9; eaveHeight: 5.6; overhang: 0.5; garage: { width: 3.6; depth: 6.5; height: 2.9; pitchDeg: 10 } }
export type PlaneFrame = { plane: RoofPlane; origin: THREE.Vector3; uAxis: THREE.Vector3; vAxis: THREE.Vector3; normal: THREE.Vector3 } // origin = eave centre
export type Anchors = { inverter: Vec3; battery: Vec3; wallbox: Vec3; car: Vec3; heatpump: Vec3; houseEntry: Vec3; sun: Vec3 }
export function buildHouse(pitchDeg: number, palette: Palette): { group: THREE.Group; frames: PlaneFrame[]; anchors: Anchors }

```
House: two storeys, gable roof with ridge along x (south plane faces +z), roof overhang + fascia, simple tile banding (a few thin strips, not per-tile), windows as inset dark-glass boxes with white frames, front door, chimney on the north plane (keeps the south plane free), attached garage on +x with mono-pitch south roof (second `PlaneFrame`), driveway slab, garage door. Battery + inverter on the garage side wall facing the driveway; wallbox beside the garage door; heat pump on the west side. Materials `MeshStandardMaterial`, roughness ~0.85, flat colours from the palette. Whole group is rotated in Scene by `(azimuth - 180)°`, not here.

### Task 5: Scene + equipment rendering

**Files:** Create `Scene.tsx`, `Equipment.tsx`, `useReducedMotion.ts`; local preview page (uncommitted).

**Interfaces — Consumes:** `buildHouse`, `slotToWorld`, `buildSceneSpec`, `getPalette`. **Produces:** `<Scene spec={SceneSpec} theme mode onSelect={(k: CompKey|null)=>void} selected={CompKey|null} preset={Preset} />` (Preset defined in Task 7).

- Canvas (in House3D, Task 8): `shadows`, `dpr={[1,2]}`, `gl={{ antialias: true, preserveDrawingBuffer: true }}`, camera fov 35. Lights: hemisphere (sky/ground from palette) + one directional sun with 1024² PCFSoft shadow map, `ContactShadows` under the house. Background = palette.surface0, soft fog to the same colour.
- Panels: one `InstancedMesh` (box 1.134×1.762×0.04, dark blue-black glass `#1d2633` with a thin `panelFrame` edge via second instanced mesh or emissive edge) placed via `slotToWorld(...,lift 0.12)` and oriented by the frame normal.
- Appear/disappear: each item has a target `t ∈ {0,1}`; `useFrame` damps `THREE.MathUtils.damp(cur, t, 10, dt)`; panel `i` uses delay `min(i*25ms, 500ms)` and drops 0.6 m + scales from 0.85; components scale 0.85→1 with a short overshoot-free ease; removed items stay mounted until cur < 0.01. Reduced motion → snap. State is keyed by slot id / CompKey so a refine only animates what changed.
- Equipment meshes (low-poly, a few boxes/cylinders each): inverter (white box + small display), battery (taller white cabinet with comp-battery stripe), wallbox (dark unit + comp-wallbox cable) + simple car silhouette on the driveway when wallbox visible, heat pump (white box, fan grille ring in comp-heatpump).

### Task 8: Public component + static fallback

**Files:** Create `House3D.tsx`, `renderMode.ts`, `__tests__/renderMode.test.ts`, `web/public/models/house-fallback.png`; `index.ts` re-exporting `House3D`.

**Interfaces — Produces:**
```ts
export type RenderMode = "3d" | "static"
export function chooseRenderMode(env: { webgl: boolean; saveData?: boolean; cores?: number; forceStatic?: boolean }): RenderMode
export function House3D(props: { design: DesignResponse; home: Home; mode: House3DMode; roof?: RoofInput; static?: boolean; className?: string }): JSX.Element
```
- `chooseRenderMode`: static if `forceStatic`, `!webgl`, `saveData`, or `cores <= 2`; else 3d.
- `House3D` ("use client"): detects env in an effect (SSR renders the static image first, so server render never touches WebGL), lazy-loads the canvas with `next/dynamic(..., { ssr: false })`, static image shown until the canvas reports first frame, then cross-fades (200 ms). Preset pills (Overview · Roof · Garage) bottom-left as secondary pills; planner mode adds a "Save image" pill → `canvas.toDataURL("image/png")` download (for slides). Theme from `document.documentElement.classList.contains("dark")`. Container aspect 4/3 on mobile, 16/10 ≥ md, `aria-label` describing the system in words (e.g. "House with 20 solar panels, a 10 kWh battery and a car charger").
- Fallback PNG: captured with the Save image button from the preview at 1600×1000 and committed.
